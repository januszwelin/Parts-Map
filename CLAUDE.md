## What the app is

A spatial canvas for Internal Family Systems (IFS) parts work: a person names inner "parts," places each on a thin scalable body outline, and draws directional arrows between them. It is a contemplative, therapeutic tool, used heavily on phones. **The top priority is feel** — dragging, the lift interaction, and arrow-drawing must be Miro-grade fluid. When a feature conflicts with fluid motion, preserve the motion.

## Locked architectural decisions

These are decided in the spec; do not re-litigate them:

- **Location is text-authoritative.** Each part stores a canonical location (a named region key + front/back depth) as the source of truth; the render x,y is *derived* from the region's anchor and current body scale, never stored authoritatively. Editing the location text moves the node; dragging only *proposes* a location (nearest region). Off-body parts are the exception: they use a stored `freePos` and are exempt from body scaling. *(A short-lived 2026-07-04 `tweak` amendment allowed sub-region fine placement; it was **repealed 2026-07-05** — "it should snap to the nearest point that's pulsing" — so on-body parts sit exactly on anchors again. `parseMap` simply ignores `tweak` in old save files.)*
- **Region config is data, not logic.** A single editable array of `{ key, label, anchor: {x,y} normalized 0–1, hasBack }` (full vocabulary in spec Appendix A). Back anchors are offset a few pixels from front so nodes never perfectly stack. It must be changeable without touching app behavior.
- **Left/right are anatomical** (the person's own body): their right appears on the viewer's left in the front view.
- **Single source of truth for parts.** One parts array feeds both the canvas and the side list panel — two views, one dataset, no syncing.
- **Persistence behind a seam.** v1 is a self-contained React app with in-memory state and JSON file save/load (no backend, no login, no localStorage). Keep save/load in a small module so swapping in a database later is a localized change. Round-trip everything: parts, locations, colors, arrows, body size.
- **Manual body scaling first, auto-crowding second.** Build the size slider rock-solid, then add auto-scaling as a tunable, toggleable layer. Auto-scaling nudges gently, only when genuinely crowded, and never moves what the user just placed.
- **Signature interaction — the lift.** Grabbing a part raises it (deeper shadow) with a leader line to a target indicator that magnet-snaps to region anchors; dragging slightly past a region with a back counterpart "pops" the target to the back anchor (filled dot = front, hollow "back" ring = back). Back-of-body parts carry a persistent visual cue (dashed border or "back" tag).
- **Mobile gesture model:** one finger on empty canvas pans; one finger on a part drags it; pinch zooms. The lift indicator is offset from the fingertip.
- **AI location interpretation is batch-only** (at paste/import time), targeting a standard production model (e.g. Sonnet). For the prototype, a simple text matcher with a clear seam for the AI call is sufficient.
- **Library choice:** a node/edge canvas library (React Flow suggested; tldraw an alternative) may do the heavy lifting, but the body-coordinate system, lift, magnet pop, and auto-scaling are bespoke layers on top.

## Decisions added 2026-07 (client-driven, spec'd in parts_map_ui_enhancement_prompt.md)

- **Arrow relationship labels:** the original "no relationship typing" rule is repealed. Arrows carry an optional short free-text label ("manages," "protects," …), edited in the arrow popover, rendered as a quiet midpoint pill, round-tripped through JSON save/load.
- **Flowchart text export:** the parts list panel has a "Copy Relationships" button exporting all arrows as plain text, one per line: `[Source Part Name] -> label -> [Target Part Name]` (unlabeled: `[Source] -> [Target]`), roots-first depth-first order.
- **Body redesign — side-by-side front + back figures (2026-07-04, supersedes the 2.5D flip):** the silhouette is vector-traced from the client-supplied `Human_silhoutte.svg` (a raster inside an SVG shell). Front and back render as two labeled figures side by side, both always visible; the back figure is mirrored (seen from behind) with spine/blade hints. **Depth = which figure a part sits on** — there is no rotate control, no viewMix, and no magnet "pop-through"; you reach the back by dragging to the back figure. The text-authoritative location model is unchanged. **Not** free-orbit 3D (no Three.js) — that stays future. Note: `parts_map_spec.md` and `parts_map_ui_enhancement_prompt.md` still describe the flip; this bullet is authoritative until they're revised.
- **Drag feel (2026-07-04, landing rule revised 2026-07-05):** **the cursor holds the card by its center** — once a drag has truly begun (~12 px of travel; a mere grab never moves a placed part), the card's center is recomputed from the live pointer every frame, so the focus-assist zoom's camera glides can never separate card from cursor (React Flow's own flow-space grab offset would otherwise amplify with zoom). **The magnet owns the landing** (supersedes the 2026-07-04 "gentle assist" fine placement): while aiming over a figure, the nearest anchor carries a soft breathing **pulse ring** (`anchor-pulse`, static under reduced motion) around the landing dot, and the drop **always lands on that pulsing anchor** — off-body drops still land freely at the release point. The magnet is **aim-gated** — above ~750 screen px/s the hand is "in transit" (indicator becomes a quiet dot trailing the pointer, no anchor claims, no ticks; hand-speed is a time-based EMA of raw client px, never flow coords), and slowing under ~380 px/s commits the nearest target with one soft tick; while aiming, the sticky magnet holds (held anchor yields only to a decisively closer rival). Dwell-gated focus-assist zoom eases in over dense anchor clusters, pivots on the pointer, eases back on drop (skipped under reduced motion). **Landing choreography:** on release the card glides to the anchor (220 ms nearby, stretching to 320 ms for long glides) while its lift/tilt relaxes, and the impact squash, accent ripple, thump, and haptic all fire at touchdown, never at release; `cancelSettle` cleans up if a new grab interrupts mid-settle. A local **spotlight** brightens only the anchor dots near the pointer. **Sound (2026-07-04):** four tiny synthesized Web Audio cues (pickup blip, magnet tick, landing thump, off-body set-down) behind a session-only toolbar mute toggle — lazy AudioContext with gesture-listener unlock for iOS; no audio assets.
- **Tap-to-place Add (2026-07-05, replaces the viewport tray):** pressing Add does **not** create the part — it enters a brief placement mode: a ghost card (the part-to-be) follows the pointer, the anchor constellation brightens, the nearest anchor pulses with the same leader/dot language as a drag, and a hint pill names the mode ("Tap where X lives" + ✕). One tap on/near a figure creates the part on that anchor with the full landing choreography; a tap on open canvas creates it off-body right there. Escape / ✕ / opening Import cancels and hands the typed name back to the input (nothing created); pressing Add with a new name replaces the ghost. Capture-phase listeners own the canvas during the mode (no panning, no accidental node selection); toolbar/panels are exempt via `data-ui-chrome`. The Add input's text state lives in the app (not the Toolbar) so cancel can restore it. Bulk **import** fallback spawns beside the body via `offBodySuggestion`, not in a screen corner.
- **Phone camera (2026-07-05):** on screens narrower than 640 px the initial camera frames the **front figure** comfortably (instead of both figures tiny), and a phone-only floating **Front/Back pill** (top-center, matches the figure captions) glides the camera 380 ms between figure centers at the current zoom — it moves the camera only, never a mode; the active segment tracks which side of flow x = 0 the screen center is on, so pinch/pan keeps it honest.
- **Phone edit sheet (2026-07-05):** on phone layouts (`useIsPhone`, the `sm` breakpoint) selecting a part opens a **bottom sheet editor** instead of the floating popover — thumb-sized rows for name, color, text size/bold, shape, location, and a **front/back surface toggle** (shown only where the part's own region has both surfaces; flips via `api.setDepth`, gliding with the same settle as a drop). Swipe the grab strip down (or Done, or tap the canvas) to put it away; it hides during drags/placement so it never covers a landing. Desktop keeps the popover, which also gained the **name field** — renaming didn't exist anywhere before. Tap-to-place does **not** auto-select on phone (the sheet would bury the landing choreography).
- **Auto-space (2026-07-05, replaces "auto-grow" in behavior and label):** the old pass was silently dead — its `useNodesInitialized` gate never turned true in this controlled setup, which is why it "never seemed to do anything." Now armed placements/deletions trigger one **decisive** move: grow straight to the scale that clears the worst crowding (4% cushion, ×1.5 cap per pass), or **relax back** when ≥12% slack opens up (never below the hand-set slider value, tracked in `manualScaleRef`; fewer than 2 on-body parts relaxes fully to that floor). Every move announces itself in a quiet pill with one-tap **Undo**. On phone layouts the camera rides along inside `animateBodyScale`: the framed figure holds its screen position and size (zoom compensates 1/scale), so making room reads as cards spreading — the body never outgrows a small screen; desktop grows about the scene center as before.

## Later phases (not in the v1 prototype)

Auth (one shared provider — Clerk or Supabase Auth — across all DMC tools on subdomains of one domain), per-user database persistence, and Circle integration (open in its own tab, not an inline iframe, because third-party-cookie deprecation breaks embedded sign-in) come after the prototype, per the handoff checklist. Saved maps are sensitive psychological data — privacy decisions are deliberate, not defaults.
